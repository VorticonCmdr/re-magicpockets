Full-screen pictures in [[Magic Pockets]] are stored in <tt>.pip</tt> files, compressed with [[Magic Pockets RNC Compression|RNC method 1]]. After decompression they have an Atari ST DEGAS low-resolution layout, with word-interleaved bitplanes. The short <tt>intro5.pip</tt> caption-font resource uses the same header and pixel organisation but only 64 rows.

== File format ==

The ordinary 320&times;200 files are 32066 bytes:

{|class="wikitable"
!Offset!!Data type!!Name!!Description
|-
|<tt>0x0000</tt>||UINT16BE||resolution||DEGAS resolution word; low-resolution pictures use 0
|-
|<tt>0x0002</tt>||UINT16BE[16]||palette||16 Atari ST palette words
|-
|<tt>0x0022</tt>||BYTE[32000]||bitmap||200 rows of 160 bytes each
|-
|<tt>0x7D22</tt>||BYTE[32]||cycling||DEGAS Elite colour-cycle data; fields not interpreted by the repo
|}

<tt>intro5.pip</tt> is 10274 bytes: the 34-byte header and 10240 bitmap bytes for 64 rows. It has no 32-byte cycle trailer. There is no additional height field; choose the known resource layout or derive the short bitmap size from its length.

=== Palette ===

Each palette entry is a big-endian <tt>0x0RGB</tt> word with three bits per component. These embedded colours are metadata, not necessarily the palette actually displayed by the DOS game. <tt>INTROU.EXE</tt> uses its own palette banks at <tt>DS:BC9E</tt>; the game pictures use executable-resident world palettes. Use the relevant runtime palette to reproduce the original screen.

=== Bitmap ===

Each row contains 20 groups of 16 pixels. Each group is eight bytes: a big-endian 16-bit word for plane 0, then planes 1, 2 and 3. Plane ''k'' supplies colour-index bit ''k''; bit 15 is the group's leftmost pixel.

 word offset = 0x22 + y * 160 + floor(x / 16) * 8 + plane * 2
 bit number = 15 - (x % 16)

There is no mask plane or transparent colour rule. Do not interpret the plane words as little-endian: that swaps the two eight-pixel halves of each group.

=== Displayed height ===

<tt>GAMEU.EXE</tt> draws 192 rows of <tt>new.pip</tt> and <tt>endscrn.pip</tt>, leaving eight stored rows unused. <tt>INTROU.EXE</tt> uploads all 200 rows of the ordinary intro pictures. The 1312 bytes once described as unexplained trailing data are eight bitmap rows plus the 32-byte cycle trailer.
