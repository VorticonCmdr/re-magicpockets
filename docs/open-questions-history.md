## Open questions — ranked

1. `UNKNOWN_autoplay_format` — **OPEN, lead only.** `data/autoplay.pin` (RNC-packed, unpacks to 2000 bytes; `GAMEU.EXE` contains the string `autoplay.pin`) looks like `(count,state)` byte pairs: 315 pairs before the first `00 00`, counts summing to 2597. Hypothesis: it is the attract-demo tape that `Demo_PlaybackInput` (`1000:0159`) replays from `[8ba6]`. The state values seen (`0x08`, `0x80`, `0x88`) do not obviously match `web/engine/input.js`'s 5-bit mask. `docs/formats/pin.md` lists the file as "Not decoded". `[UNKNOWN]` — confirm by disassembling `Demo_PlaybackInput` and the file open. This is the gate for any DOSBox tick-parity harness.
2. `UNKNOWN_logic_hz` — **OPEN.** `docs/port-plan.md` concludes the main loop is paced by vsync and the ~50.15 Hz timer ISR drives sound, so the port uses `requestAnimationFrame`. That was not traced against the real frame counter. gods-web's equivalent turned out to be an exact 15 Hz derived from the PIT divisor and a wait on a counter. `[UNKNOWN]` — read `Video_WaitVsyncAndCountFrame`'s wait condition and measure live.
3. `UNKNOWN_player_entity_slot` — **OPEN, contradictory evidence.** `docs/port-plan.md` records a live read finding entity slot 1 (type 3, X=144, Y=80) that never moved across minutes of play, while slot 0 (type 1) tracked `[0x8bbb]/[0x8bbd]`. Every `.pin` level has an identical type-3 record at (144, 80), so it is authoring boilerplate, not a spawn point. Which slot is the player is not settled. `[UNKNOWN]`.
4. `UNKNOWN_level_spawn_positions` — **OPEN.** Real per-level start positions come from a per-sublevel "camera position" table at `6de3:0000` that is all zero in the static image and populated through a computed pointer (no Ghidra xrefs). Until it is found, `web/engine/real-terrain.js` uses a generic standable-spot search for all 8 levels. `[UNKNOWN]`.
5. `UNKNOWN_frame_source_mode_0` — **OPEN.** Indirect near-pointer tile-stream sprite addressing (`frameSourceMode === 0`: about 30% of bank 7 entities, most of bank 2, some of bank 3, and the player's own descriptor). The player draws one fixed standing tile (`PLAYER_SPRITE_GLOBAL_INDEX = 60`) and affected enemies fall back to a dot. `[UNKNOWN]`.
6. `UNKNOWN_entity_default_scripts` — **OPEN.** The default-script tables at `0xcd88` and `0xd996` (and the bytecode they point at) are not dumped, so `Entity_RunScript`'s 78-opcode VM (`web/engine/entity-script-vm.js`) has no real script to run; only about 11 opcodes have handlers. `[UNKNOWN]`.
7. `UNKNOWN_ground_collision_dispatch` — **OPEN.** `Entity_ResolveGroundCollision` (`1000:e14f`) and its `Entity_ScanGround*` helpers are undecoded; `web/engine/collision.js` is a generic tile-AABB stand-in. The per-tile table at `6de3:f189` is dumped and byte-verified (`npm run verify`). `[UNKNOWN]` for the dispatch; table contents `[PROVEN]` against `GAMEU.EXE` file offset 447225.
8. `UNKNOWN_ground_table_1_vs_16` — **OPEN.** Table entries are `0` passable, `1` solid, `16` "special"; the meaning of `16` (ladder? hazard?) is unconfirmed, and the port treats `16` as solid. `[UNKNOWN]`.
9. `UNKNOWN_alt_ground_table_extent` — **OPEN, opened by the first verify run.** `docs/engine.md` says a second, stricter table sits at `6de3:f27b` ("near-identical, every 16 replaced by 0"). But `0xf27b - 0xf189 = 0xf2`, so a 256-byte table there overlaps the last 14 bytes of the default table; compared byte-for-byte at that offset, 67 entries differ other than 16→0. The "near-identical" claim was probably read from a table of a different length or base. `[STATIC]` contradiction between two addresses; needs a live `read_memory`.
10. `UNKNOWN_hud_glyph_mapping` — **OPEN.** `Hud_UpdateScoreDisplay` writes custom glyph codes (offset from ASCII by `-0x44`/`+0xBC`), but the glyph-to-tile mapping inside `extras.pak` is unresolved; the port draws HUD text with plain canvas text. `[UNKNOWN]`.
11. `UNKNOWN_sfx_event_ids` — **OPEN.** Table entry N is sound id N (`docs/formats/pin.md`), but which id belongs to which gameplay event is not decoded; `web/audio/sound-manager.js` uses arbitrary picks. Only `adlib.pin` id 11 (World-4 ending fanfare) is confirmed. `[UNKNOWN]`.
12. `UNKNOWN_opl2_streams` — **OPEN.** The native OPL2 register-stream format in `adlib2/adlib3/sblaster.pin` is undecoded; audio is MIDI-only through an oscillator synth. `[UNKNOWN]`.
13. `UNKNOWN_rng_carry_in` — **OPEN.** `web/engine/rng.js` ports `Rng_NextValue` (`1000:11fc`) assuming the CPU carry flag is 0 on entry, so it is not trace-exact. The seed source is also unknown. `[STATIC]`.
14. `UNKNOWN_room_warp_origins` — **OPEN.** `FUN_1000_59a9` warps between rooms using trigger anchors; the per-room coordinate origins (the negative-XY "noise band" in `.pin` records) and the mapping of sub-level entries 2–12 to the two `.pap` maps per world are unresolved. `[STATIC]` structure, origins `[UNKNOWN]`.
15. `UNKNOWN_entity_behavior_leaves` — **OPEN.** About 34 leaf kind-handler functions behind `Entity_DispatchUpdateByKind` / `Entity_DispatchHitReactionByKind` are unnamed in `symbols/gameu.json`; AI uses the real dispatch table but approximate behaviour. `[STATIC]` for the dispatch, `[UNKNOWN]` for the leaves.
16. `UNKNOWN_palette_fade` — **OPEN.** `Fx_UpdateTransition` is a 24-bank VGA palette fade; the port uses a black alpha overlay instead. `[STATIC]`.
17. `UNKNOWN_pickup_identification` — **OPEN.** Pickups and bonus items are never authored in level scripts (`[STATIC]`: zero matches against the ten bonus type values across all six census files); they come from the runtime queue at `[8bb5]`. How a pickup is identified at runtime is unresolved, so the port's pickups and exit zone are placeholders. `[UNKNOWN]`.
